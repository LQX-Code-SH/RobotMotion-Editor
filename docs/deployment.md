# 部署方式与演进路线

## 1. 当前决策：本地安装 + 启动弹出浏览器

**已选定，按此执行；正式交付不走公网托管。**

实现现状：

- 开发态：`pnpm dev` 已配置 `server.open: true`，启动后自动打开浏览器（`http://localhost:3000`）
- 生产态：`pnpm build` 产出 `dist/`，尚缺"一键启动本地静态服务并打开浏览器"的启动脚本（待补，可用 `vite preview --open` 或独立的本地启动器）

```
本地安装包 / 本地启动脚本
        │
        ├─ 启动本地静态服务（页面从 127.0.0.1 加载，HTTP）
        └─ 自动打开系统默认浏览器
                 │
                 └─ 浏览器直连局域网机器人：ws://<robot-ip>:8081 / 8082 / 8083
```

理由：

- 页面与机器人在同一局域网，`ws://` 明文直连，**不需要域名、不需要证书、不需要备案**
- 不依赖外网，现场断网也能用；模型资源走本地目录，无 400MB 级下载
- 真机控制链路最短（浏览器 → 机器人桥接），延迟与故障点最少
- SSH 远程安装、设备发现（UDP beacon）、文件加载等功能都在同一网络内完成

结论：正式使用与现场交付一律走该形态；公网托管只用于**演示**（不含真机控制），不作为交付方式。

## 2. 未来可选项：边缘网关 + TLS（暂不开发）

**状态：方案已记录，待条件成熟再启动。**

用于满足"公网页面 + 远程控制局域网机器人"的需求。核心原则：

> 机器人本体**不需要公网 IP，也不暴露公网**；需要被浏览器访问到的是网关，TLS 只加在网关这一跳。

### 2.1 拓扑

```
┌──────────┐   https/wss   ┌─────────────┐   内网 ws    ┌──────────────┐
│ 浏览器    │ ────────────► │ 边缘网关     │ ──────────► │ 机器人本体     │
│ (公网页面) │   443 端口    │ station.js   │  8081/8082   │ bridge（明文） │
└──────────┘               │ + TLS 终止   │  8083 相机    └──────────────┘
                           └─────────────┘
```

### 2.2 网关可达性的四种形态

| 形态 | 网关侧公网 IP | 入站端口 | 安全暴露面 | 适用 |
|---|---|---|---|---|
| C-1 端口映射 | 需要（路由器有公网 IP） | 443 | 中 | 有固定公网 IP 的实验室 |
| **C-2 云反代 + 隧道（推荐）** | 不需要 | 不需要（主动出站） | 小 | 大多数生产场景 |
| C-3 VPN 组网（Tailscale / WireGuard） | 不需要 | 不需要 | 最小 | 内部团队、多机器人 |
| C-4 纯内网 + 域名 | 不需要 | 不需要 | 无 | 仅内网用户，但要消除混合内容 |

C-2 参考链路：`浏览器 → 云 VPS（Nginx，443，证书）→ 隧道（frp / cloudflared / ssh -R）→ 边缘网关 → 机器人`。

### 2.3 证书策略

| 方式 | 说明 |
|---|---|
| 域名 + DNS-01（推荐） | `gw.example.com`，acme.sh / certbot 自动续期；域名解析到内网 IP 也能签发 |
| 云反代终止 TLS | 证书只装在 VPS，隧道内明文，运维最省事 |
| 自签 / 企业 CA | 仅限封闭车队，需给每台操作电脑下发 CA，体验较差 |

注意：公共 CA 不签 IP 证书，因此 TLS 方案**必须持有域名**（可与公网解析解耦）；中国大陆服务器对外 80/443 还需 ICP 备案，境外 VPS 或隧道不需要。

### 2.4 网关职责与现状差距

| 能力 | `bridge/station.js` 现状 | 需要补充 |
|---|---|---|
| WebSocket 代理（control / status / camera） | ✅ 已有 | — |
| 设备发现与列表（UDP beacon + `/api/devices`） | ✅ 已有 | — |
| 远程运维管理器（独立 GUI / 脚本，直连 SSH） | ✅ 已有 | — |
| TLS 终止 | ❌ | `https.createServer` + 证书参数，或前置 Nginx |
| 鉴权 | ❌（CORS 为 `*`） | Bearer token / 短时 JWT，按设备授权 |
| Origin 白名单 | ❌ | 防 CSWSH（恶意网页借用户浏览器驱动机器人） |
| PNA 预检头 | ❌ | `Access-Control-Allow-Private-Network: true` |
| 审计日志 / 限速 | ❌ | 指令审计、控制限频、相机并发限制 |
| 常驻运维 | ❌ | systemd / pm2、开机自启、健康检查、证书续期 |

端口原则：**对外只开 443**，8081/8082/8083/22 一律不出内网。

### 2.5 前端改造点

- `src/features/robot/RobotConnectionUI.js`：`stationUrl` 目前只支持 `http://host:8090`，需支持显式 `https://`，并把 `ws` 升级为 `wss`
- 相机通道经网关同源代理，避免图片/流被混合内容拦截
- 连接区增加"网关模式 / 直连模式"提示，明确当前链路

### 2.6 启动条件（满足任一再开发）

- 出现跨地域/多操作员的远程控制需求，本地安装形态无法覆盖
- 需要集中管理多台机器人并留存操作审计
- 现场网络无法安装本地客户端（如平板、受限终端）

### 2.7 验收标准（开发时）

1. 公网 HTTPS 页面可连接 `wss://` 网关，无混合内容报错、无证书告警
2. 未携带有效 token 的连接一律拒绝，且不影响直连模式
3. 网关停机时前端给出明确提示，直连模式仍可正常工作
4. 相机通道在公网链路可降帧/按需开启，不拖垮控制通道

## 3. 明确不采用的方案

- **GitHub Pages 作为正式部署**：内置机型资源约 399MB，超出免费额度与带宽预期；无法配置 COOP/COEP（USD 查看器依赖 `SharedArrayBuffer`）；强制 HTTPS 反而增加网关与证书成本。仅可用于不含真机控制的演示站。
